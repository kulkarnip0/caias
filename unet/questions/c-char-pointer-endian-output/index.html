What does a char* see when it points to an int?

Question

#include <stdio.h>
int main()
{
    int a = 320;
    char *ptr;
    ptr = (char*) &a;
    printf("%d", *ptr);
    return 0;
}

Options: A) 2    B) 320    C) 64    D) Compilation error

Key idea: &a gives the starting address of the integer. Casting that address to char* does not move it. It only says: “when I dereference this pointer, read one char-sized piece — one byte.”

1. First understand the storage sizes

For this exam question, use the usual machine model:

char = 1 byte = 8 bits int = 4 bytes = 32 bits

So imagine one integer as four neighbouring 8-bit boxes:

Important: a char* can therefore inspect an int one byte at a time.

2. Convert 320 into binary

Break 320 into powers of two:

320 = 256 + 64 = 2⁸ + 2⁶

Therefore:

320₁₀ = 101000000₂

But our int is 32 bits, so add leading zeros:

00000000 00000000 00000001 01000000

Now the 32-bit integer is visibly split into four 8-bit bytes.

The cast does not convert 320 into a character. It does not change the address. It changes only the pointer type.

Same place in memory, different reading size.

7. Why does *ptr read only 8 bits?

Because ptr is a char*. Dereferencing a pointer reads one object of the pointed-to type.

int* → dereference → read an int-sized object char* → dereference → read a char-sized object

9. Final output

printf("%d", *ptr);

*ptr is the value of the first byte, which is 64 on the little-endian machine assumed by this MCQ.

Expected answer: C) 64.
Accuracy note: the C language does not require a 32-bit int, nor does it require little-endian byte order. This question clearly expects the common model of 8-bit bytes, 32-bit int, and little-endian storage. On a big-endian machine, the first byte of this representation would be 0x00.

One picture to remember

a = 320 32-bit int: 00000000 00000000 00000001 01000000 little-endian memory: [01000000] [00000001] [00000000] [00000000] ↑ ptr char* reads only 8 bits 01000000₂ = 64
Whenever you see (char*)&some_integer, think: “same address, but now I am looking at the integer one byte at a time.”
