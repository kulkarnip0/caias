OPERATING SYSTEMS · UNIT I

A program is still. A process is alive.

A program becomes a process when its instructions begin executing. The operating system must then manage the CPU, memory, I/O resources, process state, communication and coordination needed for that process to run safely and efficiently.

📄

Program

Instructions stored on disk.

⚙️

01 · UNDERSTANDING PROCESS MANAGEMENT
Real life example to understand

Restaurant analogy

Think of the operating system as a restaurant manager, the CPU as the chef, a program as the recipe and a process as a customer order being prepared. Orders waiting for the chef are like processes in the Ready state. An order waiting for ingredients is like a blocked process waiting for I/O.

Customer order→Ready queue→Chef / CPU→May wait for ingredient / I/O→Back to ready→Completed

The OS coordinates processes that compete for shared resources.

Many processes may exist at the same time and may require the same processor, memory or I/O device. The OS therefore has to manage both processes and resources so that the system remains efficient and consistent.

🗓️Schedule

Choose which ready process gets the CPU.

➕Create / Terminate

Build and later remove process-management information.

⏸️Suspend / Resume

Temporarily stop and later continue a process.

🔐Synchronize

Coordinate access to shared resources.

💬Communicate

Support information exchange between processes.

⚠️Handle Deadlocks

Keep cyclic resource waiting from stopping progress.

02 · PROCESS STATES

A process changes state as it moves through its life cycle.

New

Being created.

Ready

Waiting for CPU.

Running

Executing on CPU.

Waiting

Waiting for an event or I/O.

Suspended Ready

Ready but temporarily suspended.

Suspended Block

Waiting and temporarily suspended.

Terminated

Execution finished.

New→Ready→Running→Waiting→Ready→Running→Terminated
03 · PROCESS CONTROL BLOCK (PCB)

The PCB is the OS record for a process.

Each process is represented by a Process Control Block containing information needed to identify, schedule, pause and later restore that process.

PCB fieldPurpose
Process IDUnique identifier for the process.
Process StateCurrent state such as Ready, Running or Waiting.
CPU RegistersRegister values that must be restored later.
Program CounterAddress of the next instruction to execute.
Memory Management InformationInformation about memory allocated to the process.
I/O Status InformationInformation about I/O devices and operations assigned to the process.
Simple picture: the PCB works like a detailed bookmark. The OS can stop a process, store its place and state, run something else, then return later.
04 · PROCESS MANAGEMENT TASKS

What does the OS actually do for processes?

Process Creation & Termination

Creation includes generating a process ID, setting up the PCB and preparing the new process. Termination may be performed by the OS or a parent process and includes releasing resources allocated to the process.

CPU Scheduling

In a multiprogramming system, several processes may need the CPU. The OS must select processes so execution remains smooth and efficient.

Inter-Process Communication

Cooperating processes may exchange information using facilities such as shared memory and message passing.

Process Synchronization

Synchronization coordinates multiple processes so access to shared resources such as memory happens in a controlled and predictable manner.

Deadlock Handling

The OS must prevent or handle situations where two or more processes cannot proceed because of cyclic resource dependencies.

05 · PROCESS OPERATIONS

State changes require concrete OS operations.

1

Create

Create a process instance, assign a PID and build its PCB.

2

Schedule

Place the ready process in the ready queue and allow the scheduler to select it.

3

Execute

The CPU executes the process. During execution it may request I/O, become blocked or be preempted.

4

Block / Wake Up

A process can block while waiting for an event and later wake up when that event occurs.

5

Terminate / Kill

When work is complete, the OS ends the process, releases its resources and removes its PCB.

06 · CONTEXT SWITCHING

Saving one process and restoring another makes multitasking possible.

Context switching is the process of saving the state of the currently running process and loading the state of another process. It can happen when a higher-priority process becomes ready, an interrupt occurs, or preemptive CPU scheduling is used.

P1 Running→Save P1 registers & PC in PCB→Choose P2→Restore P2 state→P2 Running
Context switching improves multitasking and CPU utilization, but excessive switching creates overhead because CPU time is spent saving and restoring state.
07 · SCHEDULING ALGORITHMS

Different schedulers choose the next process using different rules.

FCFS

First-Come, First-Served

Processes execute in the order in which they arrive.

P1→P2→P3
SJF

Shortest Job First

The process with the shortest CPU burst time is selected first.

3 ms→5 ms→9 ms
RR

Round Robin

Each process receives a fixed time slice. Unfinished processes return to the ready queue.

P1→P2→P3→P1
PRIORITY

Priority Scheduling

Processes are selected according to their assigned priority.

High→Medium→Low
MLQ

Multilevel Queue

Processes are divided into multiple queues and each queue can use its own scheduling method.

System→Interactive→Batch
08 · DEADLOCK HANDLING

A deadlock is a waiting cycle in which nobody can proceed.

Deadlock can occur when processes hold resources while waiting for other resources held by other processes. The dependency forms a cycle, so every process in that cycle remains stuck.

P1

Holds the printer.
Waiting for the scanner.

⇄

P2

Holds the scanner.
Waiting for the printer.

Prevention

Design the resource-allocation rules so deadlock conditions cannot arise.

Avoidance

Make resource-allocation decisions that keep the system in a state from which processes can still complete.

Detection

Allow allocation to continue but check whether a deadlock has occurred.

Recovery

Once detected, break the cycle by terminating or rolling back processes or reclaiming resources.

09 · CPU-BOUND VS I/O-BOUND

Some processes are limited by CPU speed; others by I/O speed.

🧮 CPU-Bound

Spends most of its time computing and uses the CPU intensively. Examples include mathematical simulations, data encryption/compression and graphics or video rendering. Its main bottleneck is CPU speed and efficiency.

Example: calculating millions of digits of π.

⌨️ I/O-Bound

Spends much of its time waiting for I/O operations. Examples include file downloads, printing documents and reading large datasets. Its main bottleneck is the speed of the I/O device or communication channel.

Example: a browser downloading a large file.
10 · ADVANTAGES & DISADVANTAGES

Advantages

Running multiple programs: multiple applications can progress at the same time.

Process isolation: different programs are kept from interfering with one another.

Fair resource use: CPU time and memory can be distributed among processes.

Smooth switching: the OS keeps the system responsive while moving between processes.

Disadvantages

Overhead: process tables, queues and scheduling use CPU time and memory.

Complexity: process management makes OS design and maintenance more complex.

Deadlocks: synchronization mechanisms can contribute to deadlock situations.

Context-switch cost: frequent switching can reduce useful CPU work.
