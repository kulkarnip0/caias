Why do computers need different binary codes?

A binary code is an agreed pattern of bits used to represent numbers, letters, symbols or control information. The important idea is that the same 0s and 1s can mean different things depending on the code being used.

Informationnumber / letter / symbol
→
Encoding ruleBCD, Gray, ASCII …
→
Bit pattern0s and 1s
→
Storage / transmissionmemory or communication

Weighted code

Every bit position has a fixed weight. In 8421 BCD the four weights are 8, 4, 2, 1.

0101 → 0×8 + 1×4 + 0×2 + 1×1 = 5

Non-weighted code

Bit positions do not have fixed arithmetic weights. Excess-3 and Gray code are common examples.

Reflective / self-complementing

Complementing the code word can produce the 9's-complement digit in codes such as 2421 and Excess-3. This is useful in decimal-complement arithmetic.

Sequential code

Successive coded values progress in sequence. 8421 BCD and Excess-3 have useful sequential behavior.

Alphanumeric code

Represents letters, digits, punctuation and control symbols. ASCII and EBCDIC belong here.

Error-control code

Adds redundancy so the receiver can detect—and in some codes correct—bit errors.

DECIMAL CODE · 8421 BCD

BCD does not convert the whole decimal number at once

Binary-Coded Decimal represents each decimal digit separately using four bits. Only the patterns for decimal 0–9 are valid; 1010–1111 are not decimal digits in 8421 BCD.

Why BCD? It is easy to convert between decimal displays and the internal code. The trade-off is that BCD generally uses more bits than pure binary and makes arithmetic more complicated.

OTHER DECIMAL CODES

2421 code

A weighted 4-bit decimal code with weights 2-4-2-1. It is self-complementing: complementary code words correspond to decimal digits that add to 9.

Excess-3 code

A non-weighted decimal code obtained by adding 3 to each decimal digit and encoding the result in 4-bit binary.

Digit 5 → 5+3=8 → 1000

Because Excess-3 is self-complementing, complementing all four bits gives the code for the 9's-complement digit. This is why it is attractive for complement-based decimal arithmetic.

GRAY CODE

Why should two neighboring values differ by only one bit?

Gray code is a non-weighted, unit-distance code: adjacent values differ in only one bit position. This reduces ambiguity in position-sensing applications where mechanical contacts may not switch at exactly the same instant.

How does the computer store the letter “A”?

The character itself is not stored in memory. A character encoding assigns it a numeric code, and that number is stored as bits.

A
→
Character encodingASCII / EBCDIC / Unicode
→
Numeric code65, C1, U+0041 …
→
Bits / bytes

ASCII

Small, simple character set

ASCII is a 7-bit character code, so it provides 128 possible code values. It covers English letters, decimal digits, punctuation and control characters.

Examples: uppercase A is hexadecimal 41 (decimal 65), and lowercase a is hexadecimal 61.

A → 1000001₂

EBCDIC

IBM-oriented 8-bit family

EBCDIC stands for Extended Binary Coded Decimal Interchange Code. It is traditionally associated with IBM host systems. EBCDIC uses code pages, so some characters can vary between code pages.

In a common EBCDIC mapping, uppercase A is hexadecimal C1 (decimal 193).

A → C1₁₆

UNICODE

One character repertoire for the world's writing systems

Unicode assigns a unique code point to each encoded character. Code points are normally written as U+..... For example, A is U+0041.

UTF-8, UTF-16 and UTF-32 are encoding forms that turn Unicode code points into code units/bytes. UTF-8 preserves ASCII byte values for ASCII characters.

A → U+0041 → UTF-8 byte 41₁₆
Important distinction: ASCII and EBCDIC are character encodings/code-page families. Unicode defines a much larger universal character repertoire and code-point system; UTF-8/UTF-16/UTF-32 define how those Unicode values are represented in computer storage.

Try: A, a, 9, ₹, ಅ or 😊.

What if one bit changes while data is travelling?

Noise can change a transmitted 0 to 1 or 1 to 0. Error-control codes add extra bits so the receiver has evidence that something went wrong.

Sender1011001
→
⚡ noise
→
Receiver1010001

PARITY BIT

Detect an odd number of bit errors

An extra bit is chosen so the total number of 1s is either even (even parity) or odd (odd parity). The receiver performs the same parity check.

Limitation: ordinary parity can miss an even number of flipped bits because the parity may remain unchanged.

BLOCK PARITY

Check rows and columns

Arrange several words in a block and add parity to rows and columns. If exactly one bit is wrong, the failing row and failing column intersect at the error position.

HAMMING CODE

Locate and correct one bad bit

Hamming code places several parity bits at positions 1, 2, 4, 8, ... . Each parity bit checks a different set of positions. The failed-check pattern forms a binary number called a syndrome, identifying the error position.

2P ≥ x + P + 1
x = information bits, P = parity bits.
