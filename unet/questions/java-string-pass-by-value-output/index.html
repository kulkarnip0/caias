Question 9 (Exam Question 42): What is the output of this Java program?

class Test {
    public static void main(String[] args) {
        Test obj = new Test();
        obj.start();
    }
    void start() {
        String stra = "do";
        String strb = method(stra);
        System.out.print(":" + stra + strb);
    }
    String method(String stra) {
        stra = stra + "good";
        System.out.print(stra);
        return "good";
    }
}

Choose the output

Start from the basics

1. What is a String?

A String stores text. String stra = "do"; means the variable stra refers to the text do.

2. What does + do with Strings?

"do" + "good" creates the combined text "dogood". Java Strings are immutable: concatenation does not modify the original String object.

3. What is a method and its parameter?

method(stra) calls another method, passing the current value of stra. The receiving String stra is a different local variable with the same name. Java passes a copy of the reference value, not the caller's variable itself.

4. What happens when the parameter is reassigned?

Inside method, stra = stra + "good" makes the local stra refer to "dogood". The caller's stra still refers to "do".

5. What is the difference between print and return?

System.out.print(stra) displays dogood on screen. return "good" sends the value "good" back to the caller, where it is assigned to strb. Returning does not itself print anything.

6. Follow the final output

The first print produces dogood. Back in start(), stra = "do" and strb = "good", so the final print produces :dogood. Both use print, so they appear on one line: dogood:dogood.

7. Common exam trap

Do not confuse stra in the caller with the parameter stra inside the method. Their names are identical, but they are separate variables. Also, print does not insert a space or newline.

Scope versus pass-by-value: understand the difference

Scope is where a variable name can be used. Pass-by-value is how the argument is transferred into a method. These are separate concepts.

Two variables with the same name

void start() {
    String stra = "do";  // caller's local variable
    method(stra);
}
void method(String stra) { // separate parameter
    stra = stra + "good";
}

The caller's stra is local to start(). The parameter stra is local to method(). Their identical names do not make them the same variable.

Primitive value example

void change(int x) { x = 20; }
int x = 10;
change(x);
System.out.println(x); // 10

The method receives a copy of the number 10. Changing that copy does not change the caller's variable.

Object reference example

For objects, Java copies the reference value, not the entire object. The caller's and callee's references initially point to the same object. Reassigning the parameter makes only that local parameter point elsewhere.

Why String is special

String is immutable. stra + "good" creates a new String. The method's parameter is reassigned to that new String; the caller's reference still points to "do".

Mutable object comparison

void change(StringBuilder sb) {
    sb.append("good");
}
StringBuilder sb = new StringBuilder("do");
change(sb);
System.out.println(sb); // dogood

Here, both references point to the same mutable object, and append changes that object. If the method instead did sb = new StringBuilder("good"), it would only reassign its local parameter, leaving the caller's object unchanged.

Exam rule: Java is always pass-by-value. For objects, the value copied is a reference. Distinguish reassigning a variable from mutating an object.

Why option 4 is correct

Java passes arguments by value. The method receives a copy of the reference to the original String. Since Strings are immutable, stra + "good" creates a new String and only reassigns the method's local parameter. The caller's stra stays "do".

The method first prints dogood and returns "good". The caller then prints :dogood. Because print does not add a newline, the combined output is:

dogood:dogood

Remember: Reassigning a parameter does not change the caller's variable.
