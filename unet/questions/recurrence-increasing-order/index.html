Arrange the recurrences in increasing order of time complexity

Do not memorize the answer. Read every recurrence as a description of a recursive job: how many child jobs are created, how much smaller each child becomes, and how much extra work is done outside recursion.

The question

Arrange the following recurrence relations in increasing order of their asymptotic running time.
A. T(n) = T(n/2) + 1
B. T(n) = 2T(n/2) + n
C. T(n) = 3T(n/3) + n
D. T(n) = 2T(n/2) + √n
E. T(n) = T(n−1) + 1

First learn how to read a recurrence

For a general form such as aT(n/b) + f(n), read the three parts separately:

a = number of jobs`2T(...)` means one job splits into 2 child recursive jobs.
n/b = size of each job`T(n/2)` means every child receives a problem of half the size.
f(n) = extra work`+ n`, `+ √n`, or `+1` is the work done in addition to recursive calls.
Think of B: 2T(n/2) + n.
At the first level there is 1 job of size n. It creates 2 jobs of size n/2. Each of those creates 2 more jobs, giving 4 jobs of size n/4. The tree becomes wider while each individual job becomes smaller.

AT(n) = T(n/2) + 1

How many jobs? Only 1 recursive job at every level. There is no branching.

How does size shrink? n → n/2 → n/4 → n/8 → ... → 1.

n | n/2 | n/4 | n/8 | ... | 1

Ask: how many times can we divide n by 2 before reaching 1? About log₂n levels. Each level does only +1 extra work.

total work ≈ 1 × number of levels = Θ(log n)

A = Θ(log n)

BT(n) = 2T(n/2) + n

2T means every job splits into 2 children. n/2 means each child has half the input.

Level 0: n → work = n / \ Level 1: n/2 n/2 → total work = n /\ /\ Level 2: n/4 n/4 n/4 n/4 → total work = n

There are about log₂n levels. Even though the number of jobs doubles, each job is half as large, so the +n-type work across one whole level stays about n.

n work/level × log n levels = Θ(n log n)

B = Θ(n log n)

CT(n) = 3T(n/3) + n

This is the same balance in a different shape. Each job creates 3 children, and every child gets one-third of the input.

Level 0: n → work = n / | \ Level 1: n/3 n/3 n/3 → total = n / / / ... \ \ \ Level 2: 9 jobs, each size n/9 → total = n

The tree has about log₃n levels. Each full level again contributes total work n.

n work/level × log₃n levels = Θ(n log n)

C = Θ(n log n)

For Big-Theta, the base of the logarithm does not matter, so log₂n and log₃n are both Θ(log n).

DT(n) = 2T(n/2) + √n

The branching is the same as B: 1, 2, 4, 8, ... jobs. But the extra work is only √n at the root.

Look at total extra work level by level:

Level 0: √n Level 1: 2√(n/2) = √2 · √n Level 2: 4√(n/4) = 2√n ...

The work per level grows as we move downward, and near the leaves there are Θ(n) tiny jobs. The leaves dominate the total.

number of leaves ≈ n ⇒ total = Θ(n)

D = Θ(n)

ET(n) = T(n−1) + 1

This one also has only one child, but notice the crucial difference from A.

A shrinks: n → n/2 → n/4 → ... only log n steps E shrinks: n → n−1 → n−2 → n−3 → ... → 1

For E, we remove only 1 from the problem size each time. Therefore we need about n levels. Every level contributes +1.

1 work/level × n levels = Θ(n)

E = Θ(n)

So in increasing order:

A < D = E < B = C

D and E have the same asymptotic order Θ(n), and B and C have the same asymptotic order Θ(n log n).
