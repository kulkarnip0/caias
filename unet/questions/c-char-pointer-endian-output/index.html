C char pointer: why does the program print 64?

Question

#include <stdio.h>
int main()
{
    int a = 320;
    char *ptr;
    ptr = (char*) &a;
    printf("%d", *ptr);
    return 0;
}

Options: A) 2    B) 320    C) 64    D) Compilation error

C ProgrammingPointersBits & BytesType CastingLittle Endian

Keep the complete explanation

This page now keeps the earlier explanation and the extra “why exactly 64?” explanation. Nothing is intentionally shortened. We will start from bits, then bytes, then memory, then pointers, and only at the end evaluate *ptr.

Main idea: a is an integer occupying several bytes. ptr points to the same starting address, but because ptr is a char*, dereferencing it reads only one byte. On the little-endian machine assumed by this MCQ, that first byte is 01000000₂ = 64.

1. First: what is an int and what is a char?

For this exam question, use the usual machine model:

char

1 byte = 8 bits

A char* reads one byte when dereferenced.

int

4 bytes = 32 bits

An int occupies four neighbouring bytes.

int a [ 8 bits ][ 8 bits ][ 8 bits ][ 8 bits ] total = 32 bits
Mental picture: one int is four 8-bit boxes. A char is one 8-bit box.

2. Put the decimal value 320 into those 32 bits

Write 320 as powers of two:

320 = 256 + 64 = 2⁸ + 2⁶

Therefore bits 8 and 6 are 1, and the other relevant bits are 0:

320₁₀ = 101000000₂

Because we are treating int as 32 bits, add leading zeros:

00000000 00000000 00000001 01000000

3. Split the integer into four bytes

Each group below is exactly 8 bits = 1 byte:

0x40
320 = 0x00000140

Two hexadecimal digits correspond to one byte, so the written value can be viewed as four bytes:

00 | 00 | 01 | 40

4. Why is the last byte 64?

This is the numerical heart of the problem. One byte has 8 bits, so it has 256 possible bit patterns, from 0 to 255.

320 = 1 × 256 + 64

That means:

higher part = 1 lowest 8-bit part = remainder = 64 320 % 256 = 64
So the lowest byte of 320 is 64. The remaining 1 goes into the next byte.

5. See 64 directly in the 8 bits

The lowest byte is 01000000. Now assign the usual bit weights:

01000000₂ = 0×128 + 1×64 + 0×32 + 0×16 + 0×8 + 0×4 + 0×2 + 0×1 = 64
01000000₂ = 0x40 = 64

6. Important: writing the number and storing it in memory are different views

When humans write the 32-bit number, we naturally write most-significant bytes first:

00 00 01 40

But a little-endian machine stores the least-significant byte at the lowest address. Therefore in memory the order is:

40 01 00 00
The value is still 320. Only the byte order in memory is different.

8. What exactly does &a mean?

&a means: “give me the address where a begins.”

if a begins at address 1000, then &a = 1000

The type of &a is int*, because it is the address of an integer.

a = 320

address 1000
← this is &a

9. What does (char*)&a do?

ptr = (char*) &a;

The cast does not convert the integer value 320 into a character. It does not move to another address. It changes the pointer type used to view the same memory.

Same address. Different pointed-to type.

10. Why does the pointer type matter?

When you dereference a pointer, C reads one object of the pointed-to type.

int *p; → *p reads one int char *p; → *p reads one char

Under the assumptions of this question:

one int = 4 bytes one char = 1 byte

So if ptr is a char*, then *ptr reads only one byte starting at address 1000.

This is the exact reason it does not print 320: *ptr is not reading all four bytes of the integer.

12. Why does printf("%d", *ptr) show a decimal number?

*ptr has type char. When passed to printf, it is promoted to int. The format specifier %d prints that promoted numeric value in decimal.

*ptr = 0x40 = 01000000₂ = 64₁₀ printf("%d", *ptr) → 64

The fact that plain char may be signed on some systems does not affect this particular byte, because 0x40 is 64 and lies safely in the positive range.

13. Follow the whole program in one chain

int a = 320 320 = 256 + 64 = 0x00000140 = 00000000 00000000 00000001 01000000 little-endian memory: address 1000 1001 1002 1003 0x40 0x01 0x00 0x00 ↑ &a ↑ ptr = (char*)&a ptr is char* → dereference reads 1 byte → reads 0x40 → 0x40 = 01000000₂ = 64 printf("%d", *ptr) → prints 64

14. What would happen on a big-endian machine?

On a big-endian machine, the bytes would be stored in the opposite order:

low address → [00] [00] [01] [40] → high address

Then a char* at &a would read the first byte 0x00, not 0x40.

Therefore 64 is not guaranteed by the C language alone. It is the intended MCQ answer under the usual assumptions of an 8-bit byte, 32-bit int, and little-endian byte order.

Answer: C) 64.
The cast changes how the memory is viewed, not the address and not the stored integer itself.
