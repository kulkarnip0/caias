Algorithms • Recurrence Relations

Arrange the recurrences in increasing order of time complexity

The goal here is not to jump to Master Theorem. We derive each recurrence from the recursion tree: number of jobs at a level × work done by one job × number of levels. Every logarithm and exponent step is unpacked.

The question

Arrange the following recurrence relations in increasing order of their asymptotic running time.
A. T(n) = T(n/2) + 1
B. T(n) = 2T(n/2) + n
C. T(n) = 3T(n/3) + n
D. T(n) = 2T(n/2) + √n
E. T(n) = T(n−1) + 1

Before solving: how to read a recurrence

For aT(n/b) + f(n), read each part separately.

a → number of recursive jobs2T(...) means every job creates 2 child jobs. At level i there are 2i jobs.
n/b → size of each jobT(n/2) means each child gets half the previous problem. At level i, size is n/2i.
f(n) → extra work per node+n, +√n, or +1 is work done outside the recursive calls.
Small logarithm toolbox used below
Meaning of logarithm: logax = y means ay = x.
Why logaa = 1: ask “to what power must a be raised to get a?” The answer is 1, because a1 = a.
Inverse identity: alogax = x, because logax is exactly the exponent that makes base a become x.
Power of a power: (ap)q = apq.
Change of base: logbn = logan / logab. The denominator is a constant, so all fixed log bases have the same Θ-growth.

AT(n) = T(n/2) + 1

Step 1 — branching. There is no coefficient before T, so it means 1T. Every job creates only one child. The tree is a chain.

Level 0: n Level 1: n/2 Level 2: n/4 = n/2² Level 3: n/8 = n/2³ ... Level k: n/2ᵏ

Step 2 — find the number of levels. Recursion stops when the subproblem becomes 1.

n / 2ᵏ = 1 n = 2ᵏ k = log₂ n
Why does k = log₂n?
By definition, log₂n asks: “2 must be raised to what power to become n?” We already have 2ᵏ = n. Therefore that power is k, so k = log₂n.

Step 3 — work per level. The extra term is +1, and there is only one node at each level.

work per level = 1 number of levels ≈ log₂ n Total = 1 + 1 + ... (log₂ n times) = Θ(log n)

A = Θ(log n)

BT(n) = 2T(n/2) + n

Step 1 — branching. The 2 means each node creates two recursive jobs.

Level 0: 1 job × size n n / \ Level 1: 2 jobs × size n/2 n/2 n/2 / \ / \ Level 2: 4 jobs × size n/4 n/4 n/4 n/4 n/4

At level i:

number of jobs = 2ⁱ size of each job = n / 2ⁱ

Step 2 — compute total +n work at one level. For a subproblem of size n/2ⁱ, its local +n term becomes n/2ⁱ.

level-i work = (number of jobs) × (work per job) = 2ⁱ × (n / 2ⁱ) = n

So every level costs n: n, n, n, n, ...

Step 3 — find depth.

n / 2ᵏ = 1 ⇒ 2ᵏ = n ⇒ k = log₂ n

Step 4 — total.

Total ≈ n × log₂ n = Θ(n log n)

B = Θ(n log n)

CT(n) = 3T(n/3) + n

Step 1 — branching. Each node creates 3 child jobs, each one-third the size.

Level 0: 1 job, size n Level 1: 3 jobs, each size n/3 Level 2: 9 jobs, each size n/9 Level i: 3ⁱ jobs, each size n/3ⁱ

Step 2 — work per level.

3ⁱ × (n / 3ⁱ) = n

Again, every complete level contributes n.

Step 3 — depth.

n / 3ᵏ = 1 ⇒ 3ᵏ = n ⇒ k = log₃ n

Step 4 — total.

Total = n × log₃ n = Θ(n log n)
Why can log₃n be written as Θ(log n)?
Using change of base:

log₃n = log₂n / log₂3.

log₂3 is just a fixed number (about 1.585). Dividing by a fixed constant changes only the constant multiplier, not the asymptotic growth.

C = Θ(n log n)

DT(n) = 2T(n/2) + √n

This is the most important derivation. The tree branches exactly like B, but the local work is √n rather than n.

Step 1 — jobs and size at each level.

At level i: number of jobs = 2ⁱ size of each job = n / 2ⁱ

Step 2 — local work of one job. Because the recurrence has +√n, a node whose input size is n/2ⁱ performs:

√(n / 2ⁱ)

Step 3 — multiply by all jobs at that level.

Wᵢ = 2ⁱ × √(n / 2ⁱ) = 2ⁱ × √n / √(2ⁱ) = 2ⁱ × √n / 2ⁱᐟ² = √n × 2ⁱ⁻ⁱᐟ² = √n × 2ⁱᐟ² = √n × (√2)ⁱ
So your √2 observation is exactly the key.
The work across levels grows by a factor of √2 each time:

Level 0: √n
Level 1: √2 · √n
Level 2: (√2)² · √n
Level 3: (√2)³ · √n
...

So the level-work sequence is geometric with scale factor √2.

Step 4 — how many levels? Since the subproblem halves each time:

n / 2ᵏ = 1 ⇒ 2ᵏ = n ⇒ k = log₂ n

Step 5 — evaluate the growth factor at the last level. Put i = log₂n into (√2)ⁱ:

(√2)^(log₂ n) = (2^(1/2))^(log₂ n) [because √2 = 2^(1/2)] = 2^((1/2) log₂ n) [(a^p)^q = a^(pq)] = (2^(log₂ n))^(1/2) [move 1/2 outside as a power] = n^(1/2) [2^(log₂ n) = n] = √n
Why is 2log₂n = n?
Suppose log₂n = x. By the definition of logarithm, 2ˣ = n. Therefore replacing x with log₂n gives 2log₂n = n.

And why is log₂2 = 1?
log₂2 asks “2 raised to what exponent equals 2?” Since 2¹ = 2, the answer is 1. More generally, logaa = 1 because a¹ = a.

Step 6 — calculate the last-level extra work.

W_last = √n × (√2)^(log₂ n) = √n × √n = n

Important: (√2)log₂n by itself is √n, not n. The full level work has another √n in front, so √n × √n = n.

Step 7 — sum all levels.

Total extra work = √n [1 + √2 + (√2)² + ... + (√2)^k]

This is a geometric series with ratio √2 > 1. When the ratio is greater than 1, the final terms dominate. Since the last-level scale is Θ(n), the entire sum is Θ(n).

Total = Θ(n)

D = Θ(n)

ET(n) = T(n−1) + 1

E has only one recursive child, like A, but it shrinks much more slowly.

Step 1 — expand repeatedly.

T(n) = T(n−1) + 1 T(n−1) = T(n−2) + 1 Therefore: T(n) = T(n−2) + 2 One more step: T(n) = T(n−3) + 3 After k steps: T(n) = T(n−k) + k

Step 2 — stop when the input reaches 1.

n − k = 1 ⇒ k = n − 1

So there are approximately n recursive levels, not log n levels.

Step 3 — total. Every level adds only 1, but we perform that constant work about n times.

Total = 1 + 1 + ... (n times) = Θ(n)
Compare A and E carefully.
A: n → n/2 → n/4 → ... reaches 1 in log₂n steps.
E: n → n−1 → n−2 → ... reaches 1 in n−1 steps.

Same one-child shape, completely different depth.

E = Θ(n)

Increasing order:

A < D = E < B = C

The useful mental model is:

total cost ≈ (number of jobs at a level) × (cost of one job) × (effect of number of levels)

For D, the exact level costs form a geometric series, so we use the dominant final level rather than literally multiplying one fixed “work per level” by the number of levels.
