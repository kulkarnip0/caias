What does a char* see when it points to an int?

Question

#include <stdio.h>
int main()
{
    int a = 320;
    char *ptr;
    ptr = (char*) &a;
    printf("%d", *ptr);
    return 0;
}

Options: A) 2    B) 320    C) 64    D) Compilation error

C ProgrammingPointersType CastingBytesEndianness

Mental picture first

An int occupies several bytes; a char* reads only one byte at a time
Key picture: &a points to the whole integer. After casting to char*, the address does not change — only the size of the piece read by dereferencing changes.
a = 320
stored as bytes
&a
cast to char*
read first byte

1. Convert 320 to hexadecimal

320 = 256 + 64 = 0x0140

Assuming a common 32-bit int, we can write it as:

0x00000140

2. See the bytes in memory

On the little-endian machines normally assumed in this type of question, the least-significant byte is stored first.

lowest address ← ptr
40
0x40 = 64
next byte
01
0x01 = 1
next byte
00
0
highest address
00
0
320 as an int → [ 40 ][ 01 ][ 00 ][ 00 ]

3. What does the cast do?

ptr = (char*) &a;

The cast does not convert the value 320 into a character. It makes ptr point to the same memory address as a, but as a pointer to one-byte char objects.

*ptr → first byte → 0x40

4. Convert that byte to decimal

0x40 = 4 × 16 + 0 = 64
Expected answer: C) 64.
Important accuracy note: the C language itself does not guarantee little-endian byte order. On a big-endian machine the first byte would be different. The option 64 tells us the exam question is assuming little-endian representation.

Remember this pattern

int*reads an entire int
char*reads one byte
castchanges how memory is interpreted, not the address itself
Whenever you see (char*)&some_integer, think: “I am looking at the integer byte-by-byte.”
