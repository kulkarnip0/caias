Hamming Code

A parity bit can tell us that something changed, but it cannot tell us which bit is wrong. Hamming code solves that problem by adding several carefully placed parity bits. Each parity bit checks a different group of positions. When the receiver combines the failed checks, the result directly identifies the position of a single erroneous bit.

Data bits→Add Hamming parity bits→Transmit→Recheck parity→Locate error→Correct bit
01 · WHY HAMMING CODE?

Detection is useful. Location is better.

Suppose a binary word is sent through a noisy communication channel or stored in memory. A bit may accidentally change from 0 to 1 or from 1 to 0. With ordinary even parity, the receiver can notice that the number of 1s is no longer even. However, one parity result gives only two possibilities: parity is correct or parity is wrong. It does not provide enough information to identify one particular bit among many positions.

Hamming code adds multiple parity bits. The important idea is that the parity bits do not all check the same positions. Their checking groups overlap in a planned way. Therefore every bit position has a unique pattern of parity checks associated with it. If one bit changes, the combination of failed checks forms a binary number that points to that exact position.

Core idea: parity bits are not added merely to say “error/no error”. They are arranged so that their combined result can answer “the error is at position 5”, “position 6”, and so on.
02 · DATA BITS AND REDUNDANT BITS

How many parity bits do we need?

Let m be the number of original data bits and r be the number of redundant or parity bits. After adding parity bits, the transmitted Hamming word contains m+r bits.

The receiver must distinguish every possible single-bit error position, plus the condition in which there is no error. Therefore the number of patterns produced by the r parity checks must be large enough.

2r ≥ m + r + 1

The left side, 2r, is the number of different binary patterns that r check bits can produce. On the right, m+r represents every possible bit position that might be wrong, and the extra +1 represents the “no error” condition.

Example: 4 data bits

Try r=2: 2²=4, but m+r+1=4+2+1=7. So 2 parity bits are not enough.

Try r=3: 2³=8 and m+r+1=4+3+1=8. The condition is satisfied. Therefore 4 data bits require 3 parity bits, giving a 7-bit Hamming word. This is commonly called Hamming (7,4).

03 · WHERE DO PARITY BITS GO?

Positions 1, 2, 4, 8, … are special.

Number the positions of the final code word starting from 1. Every position that is a power of two is reserved for a parity bit. Thus positions 1, 2, 4, 8, 16, … contain P1, P2, P4, P8, and so on. The original data bits are placed in all remaining positions.

04 · WHICH POSITIONS DOES EACH PARITY BIT CHECK?

Read the position number in binary.

P1 checks the 1's place

P1 checks positions whose binary position number has the rightmost bit equal to 1.

Positions: 1, 3, 5, 7, …

P2 checks the 2's place

P2 checks positions whose binary position number has the middle/2's bit equal to 1.

Positions: 2, 3, 6, 7, …

P4 checks the 4's place

P4 checks positions whose binary position number has the 4's bit equal to 1.

Positions: 4, 5, 6, 7, …

This overlap is deliberate. For example, position 5 is binary 101, so it belongs to P1 and P4 but not P2. Position 7 is 111, so all three parity bits check it. Every position therefore has its own unique checking pattern.

Step 1 — Calculate P1

P1 checks positions 1,3,5,7. Ignoring the unknown P1 for a moment, the data values are position 3=1, position 5=0, position 7=1. There are already two 1s, which is even. Therefore for even parity, P1=0.

Step 2 — Calculate P2

P2 checks positions 2,3,6,7. The known values are 1,1,1: three 1s, which is odd. To make the total even, P2=1.

Step 3 — Calculate P4

P4 checks positions 4,5,6,7. The known values are 0,1,1: two 1s, already even. Therefore P4=0.

06 · WHAT HAPPENS AT THE RECEIVER?

The receiver repeats the parity checks.

The receiver does not simply remove the parity bits. First it recalculates/checks P1, P2 and P4 using the received word. Each check produces a result: 0 if the even-parity condition is satisfied and 1 if that parity group fails.

The three results are combined as S4 S2 S1. This binary value is called the syndrome. If it is 000, no single-bit error is indicated. If it is non-zero, its binary value gives the position of the erroneous bit.

Error position = (S4 S2 S1)2

Suppose position 5 changes during transmission.

Check P1 group: positions 1,3,5,7

Values are 0,1,1,1 → three 1s → odd. Even parity fails, so S1=1.

Check P2 group: positions 2,3,6,7

Values are 1,1,1,1 → four 1s → even. This group passes, so S2=0.

Check P4 group: positions 4,5,6,7

Values are 0,1,1,1 → three 1s → odd. The group fails, so S4=1.

S4 S2 S1 = 1 0 1 = (5)10

The syndrome says position 5 is wrong. The receiver flips position 5 from 1 back to 0. The original valid Hamming word is restored. This is why Hamming code can perform single-error correction.

08 · COMPLETE ALGORITHM OF HAMMING CODE

Use this procedure for problems and examinations.

1

Identify the number of data bits.

Let the original message contain m bits.

2

Find the required number of parity bits.

Choose the smallest value of r satisfying 2ʳ ≥ m+r+1.

3

Create m+r positions.

Number the final code-word positions 1,2,3,…,m+r.

4

Reserve powers of two for parity.

Positions 1,2,4,8,16,… are P1,P2,P4,P8,… .

5

Place the data bits.

Fill all non-power-of-two positions with the original message bits in the convention specified by the problem.

6

Determine each parity bit's checking group.

P1 checks positions whose binary position number contains 1 in the 1's place; P2 checks those containing 1 in the 2's place; P4 checks those containing 1 in the 4's place; continue similarly.

7

Calculate parity-bit values.

For even parity, choose each parity bit so its entire group contains an even number of 1s. For odd parity, choose it so the group contains an odd number of 1s.

8

Transmit the complete Hamming word.

The sender sends both data and redundant parity bits.

9

At the receiver, repeat all parity checks.

Generate check results S1,S2,S4,S8,… using the same parity convention.

10

Form the syndrome.

Arrange the check results with the highest parity position as the most significant bit, e.g. S4 S2 S1 for Hamming (7,4).

11

Interpret the syndrome.

If syndrome = 0, no single-bit error is indicated. If syndrome ≠ 0, convert it from binary to decimal; that number is the erroneous bit position.

12

Correct the error.

Flip the identified bit: 0→1 or 1→0. Then extract the original data bits from the non-parity positions.

09 · WHAT HAMMING CODE CAN AND CANNOT DO

Know the capability before using it.

MethodSingle-bit errorDouble-bit errorCorrection
Simple parityDetectsNot reliable for all even-number errorsNo
Basic Hamming code (minimum distance 3)CorrectsCannot safely correct two-bit errorsSingle-bit correction
Extended Hamming / SECDEDCorrectsDetectsCorrect one; detect two

Adding one overall parity bit to the basic Hamming arrangement produces an extended form commonly used for SECDED: Single Error Correction, Double Error Detection. The ordinary Hamming syndrome by itself is designed around the assumption of at most one erroneous bit when correction is performed.

10 · ONE-MINUTE REVISION

The entire idea in one chain.

Find r: 2ʳ ≥ m+r+1→Parity at 1,2,4,8…→Data in remaining positions→Calculate parity→Transmit→Receiver checks→Syndrome→Flip erroneous bit
Memory trick: Powers of 2 are parity positions. The failed parity checks together spell the erroneous position in binary.
