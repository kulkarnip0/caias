COMPUTER ARCHITECTURE · UNIT I · BINARY CODES

How does a computer understand our information?

A letter, number, image or audio file must ultimately be represented by patterns of 0s and 1s before a digital computer can store, process or transmit it. Converting information into such patterns is encoding; interpreting the stored pattern again is decoding. Binary codes provide the agreed rules that make both possible.

Information→Encoding→Binary pattern→Storage / transmission→Decoding→Information
01 · WHAT IS A CODE?

A code gives meaning to a pattern of symbols.

When numbers, alphabets or words are represented by a specific group of symbols, they are encoded. The group of symbols used for the representation is called a code. In digital systems the symbols are binary digits, so a group of bits used to represent information is called a binary code.

⌨️ Character

The letter A can be represented by ASCII value 65, whose 7-bit binary pattern is 1000001.

🔢 Decimal digit

Decimal 5 can be represented in 8421 BCD as 0101.

📡 Communication

Sender and receiver must use the same coding rule; otherwise the received bits have no agreed meaning.

02 · COMPLETE CLASSIFICATION

Binary codes can be grouped by structure, property and purpose.

These categories are not mutually exclusive. A code may have more than one property. For example, Aiken 2421 is weighted and self-complementing, while Excess-3 is non-weighted and self-complementing.

03 · STEP-BY-STEP EXAMPLES FOR EACH CLASSIFICATION

Follow one example from input to final code.

The easiest way to understand each category is to watch exactly what happens at each stage.

WEIGHTED CODE

Example: decimal digit 5 in 8421 BCD

1
Start with the decimal digit.

We want to encode decimal 5.

2
Write the fixed weights.

8421 BCD has bit weights 8, 4, 2, 1.

3
Choose weights that add to 5.

5 = 4 + 1, so the 4-position and 1-position must contain 1.

4
Write the bit pattern.

8→0, 4→1, 2→0, 1→1, giving 0101.

5
Check by decoding.

0×8 + 1×4 + 0×2 + 1×1 = 5.

5 → weights 8,4,2,1 → choose 4+1 → 0101 → decode back to 5
NON-WEIGHTED CODE

Example: decimal digit 5 in Excess-3

1
Start with decimal 5.

We do not interpret Excess-3 using fixed positional weights.

2
Write natural BCD for 5.

Decimal 5 in 8421 BCD is 0101.

3
Add the Excess-3 bias.

Add 3, which is 0011.

4
Perform binary addition.

0101 + 0011 = 1000.

5
Interpret the result as Excess-3.

The code word 1000 represents decimal 5 in Excess-3.

5 → BCD 0101 → +0011 → 1000 (Excess-3)
REFLECTIVE / SELF-COMPLEMENTING

Example: Aiken 2421 code for 1 and 8

1
Take digit 1.

In Aiken 2421, decimal 1 is represented as 0001.

2
Find its 9's complement.

9 − 1 = 8.

3
Complement every bit of 0001.

0→1, 0→1, 0→1, 1→0, giving 1110.

4
Read the complemented code.

1110 is the Aiken 2421 representation of decimal 8.

1 → code 0001 → bitwise complement → 1110 → represents 8 = 9−1
SEQUENTIAL CODE

Example: moving from decimal 4 to 5 in 8421

1
Encode decimal 4.

4 in 8421 BCD is 0100.

2
Move to the next decimal value.

The next number is 5.

3
Encode 5.

5 in 8421 BCD is 0101.

4
Continue the sequence.

6→0110, 7→0111, 8→1000, 9→1001.

4:0100 → 5:0101 → 6:0110 → 7:0111 → 8:1000 → 9:1001
ALPHANUMERIC CODE

Example: uppercase A in ASCII

1
Start with the character.

The input character is uppercase A.

2
Look up the standardized ASCII value.

ASCII assigns uppercase A the decimal value 65.

3
Convert 65 to 7-bit binary.

65 = 64 + 1, so the 7-bit pattern is 1000001.

4
Store or transmit that bit pattern.

The system handles the bits 1000001.

5
Decode at the destination.

The same ASCII table maps 1000001 → 65 → A.

A → ASCII 65 → 1000001 → store/transmit → decode → A
ERROR DETECTING CODE

Example: even parity for 1011001

1
Start with data.

Data bits are 1011001.

2
Count the 1s.

There are four 1s, which is already even.

3
Choose the even-parity bit.

Parity bit = 0, because adding 0 keeps the total number of 1s even.

4
Transmit data + parity.

Suppose we append the bit: 10110010.

5
Receiver checks parity.

If one bit flips during transmission, the total number of 1s becomes odd and the checker detects an error.

1011001 → count 1s = 4 → parity 0 → transmit → parity check at receiver
ERROR CORRECTING CODE

Example: how Hamming code locates one wrong bit

1
Reserve parity positions.

Parity bits are placed at positions 1, 2, 4, 8, …

2
Place data in the remaining positions.

Data bits occupy positions such as 3, 5, 6, 7, 9, 10, 11, 12.

3
Calculate each parity bit.

Each parity bit checks a different group of positions.

4
Transmit the complete code word.

The receiver repeats the same parity checks.

5
Build the syndrome.

The failed parity checks combine into a binary position number. For a single-bit error, that number identifies the wrong bit.

6
Correct the bit.

The receiver flips the identified bit to restore the original code word.

data → insert parity positions → compute parity → transmit → syndrome → locate bit → flip bit
04 · WEIGHTED CODES & 8421 BCD

Each bit position has an assigned weight.

In a weighted code, add the weights corresponding to bit positions containing 1. The most common BCD code is 8421, where every decimal digit is independently represented using four bits.

BCD vs pure binary: decimal 59 is 0011 1011 in ordinary binary but 0101 1001 in BCD because BCD encodes 5 and 9 separately.
05 · BCD ADDITION

Invalid BCD digit sums need a correction of 6.

First perform ordinary binary addition. If the four-bit sum is greater than 1001, or if a carry is generated, add 0110.

Example: 7 + 8

0111 + 1000 = 1111

1111 represents 15, which is not a valid single BCD digit, so add 0110:

1111 + 0110 = 1 0101 → 0001 0101 = decimal 15

06 · BCD SUBTRACTION

Use complements to convert subtraction into addition.

9's-complement method

  1. Find the 9's complement of the subtrahend.
  2. Add it to the minuend.
  3. If an end carry occurs, discard it and add 1 to the remaining result.
  4. If no carry occurs, take the 9's complement of the result and attach a minus sign.

10's-complement method

  1. Find the 10's complement of the subtrahend.
  2. Add it to the minuend.
  3. If an end carry occurs, discard it; the result is positive.
  4. If no carry occurs, take the 10's complement and attach a minus sign.

09 · BINARY ↔ GRAY CONVERSION

Use XOR step by step.

Binary → Gray: 1011

  1. Copy MSB: 1.
  2. 1⊕0=1.
  3. 0⊕1=1.
  4. 1⊕1=0.

1011 → 1110

Gray → Binary: 1110

  1. Copy MSB: 1.
  2. 1⊕1=0.
  3. 0⊕1=1.
  4. 1⊕0=1.

1110 → 1011

10 · ALPHANUMERIC CODES

Binary patterns can represent letters, digits and symbols.

ASCII is a 7-bit standard character code, providing 128 code values. Uppercase A–Z have decimal values 65–90, lowercase a–z have 97–122, and characters 0–9 have 48–57. EBCDIC uses 8 bits and therefore provides 256 possible patterns. Hollerith is another historical alphanumeric coding scheme.

11 · PARITY

One extra bit can detect many transmission errors.

Even parity makes the total number of 1s even; odd parity makes it odd. A parity generator creates the parity bit and a parity checker verifies it at the receiver.

Limitation: a single parity bit detects every single-bit error and, more generally, any odd number of bit errors, but it cannot identify the wrong bit and cannot detect all even-number-of-bit-errors patterns.
12 · HAMMING CODE

Several parity checks can locate a one-bit error.

Hamming code places parity bits at positions 1, 2, 4, 8, … . The receiver combines failed parity checks into a syndrome that identifies the position of a single-bit error.

Important: standard Hamming code is single-error correcting (SEC). Adding one overall parity bit produces extended Hamming, commonly described as SECDED: Single Error Correction, Double Error Detection.
