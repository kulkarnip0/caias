COMPUTER ARCHITECTURE · UNIT I · BINARY CODES

How does a computer understand our information?

A letter, number, image or audio file must ultimately be represented by patterns of 0s and 1s before a digital computer can store, process or transmit it. Converting information into such patterns is encoding; interpreting the stored pattern again is decoding. Binary codes provide the agreed rules that make both possible.

Information→Encoding→Binary pattern→Storage / transmission→Decoding→Information
01 · WHAT IS A CODE?

A code gives meaning to a pattern of symbols.

When numbers, alphabets or words are represented by a specific group of symbols, they are encoded. The group of symbols used for the representation is called a code. In digital systems the symbols are binary digits, so a group of bits used to represent information is called a binary code.

⌨️ Character

The letter A can be represented by the ASCII value 65, whose 7-bit binary pattern is 1000001.

🔢 Decimal digit

Decimal 5 can be represented in 8421 BCD as 0101.

📡 Communication

Sender and receiver must use the same coding rule; otherwise the received bits have no agreed meaning.

02 · COMPLETE CLASSIFICATION

One code may belong to more than one category.

Binary codes can be grouped according to their structure, properties and purpose. These categories are not mutually exclusive. For example, standard Aiken 2421 is weighted and self-complementing, while Excess-3 is non-weighted and self-complementing.

03 · WEIGHTED CODES & 8421 BCD

In a weighted code, each position has an assigned weight.

To find the represented value, add the weights at positions containing 1. The most common BCD code is 8421 BCD: each decimal digit is independently represented by four bits having weights 8, 4, 2 and 1.

Digit 5

0101 → 0×8 + 1×4 + 0×2 + 1×1 = 5

Decimal 59

5 → 0101    9 → 1001

Therefore 59 in BCD is 0101 1001. Notice that each decimal digit is encoded separately.

BCD versus pure binary: decimal 59 is 0011 1011 in ordinary binary but 0101 1001 in BCD. BCD makes decimal-digit conversion convenient, but it uses bit patterns less efficiently than pure binary.
04 · BCD ADDITION

Why do we add 6 when a BCD digit becomes invalid?

Four bits can represent 0 to 15, but one BCD digit permits only 0000 to 1001 (0 to 9). First perform ordinary binary addition. If the four-bit result is greater than 1001, or a carry is produced, add 0110 (6) to correct that BCD digit.

Example: 7 + 8

0111 + 1000 = 1111

1111 is 15 and is not a valid single BCD digit. Therefore:

1111 + 0110 = 1 0101 → BCD 0001 0101 = 15

05 · BCD SUBTRACTION

Complements turn subtraction into addition.

9's-complement method

  1. Find the 9's complement of the subtrahend.
  2. Add it to the minuend using BCD addition.
  3. If an end carry occurs, discard that carry and add 1 to the remaining result (end-around carry). The answer is positive.
  4. If no carry occurs, take the 9's complement of the obtained result and attach a minus sign.

10's-complement method

  1. Find the 10's complement of the subtrahend.
  2. Add it to the minuend.
  3. If an end carry occurs, discard it; the remaining result is positive.
  4. If no carry occurs, take the 10's complement of the result and attach a minus sign.
06 · REFLECTIVE / SELF-COMPLEMENTING CODES

Complementing the bits can produce the code for the 9's-complement digit.

For the standard Aiken 2421 code, the code for 9 is the bitwise complement of the code for 0, 8 complements 1, 7 complements 2, and so on.

0 ↔ 9

0000 ↔ 1111

1 ↔ 8

0001 ↔ 1110

2 ↔ 7

0010 ↔ 1101

This is called self-complementing because complementing every bit gives the representation of 9 − digit.
07 · EXCESS-3

Start with BCD and add 3 to each decimal digit.

Excess-3 is a non-weighted decimal code. To encode a digit, take its natural 8421 BCD representation and add 0011.

08 · EXCESS-3 ARITHMETIC

The bias of +3 means the result needs correction.

For addition, first add the Excess-3 code words as binary. For each decimal digit: if a carry is produced, add 0011 to the four-bit result; if no carry is produced, subtract 0011. This compensates for the Excess-3 bias.

For subtraction: the self-complementing property can be used with the 9's-complement method. Keep the complement step, binary addition, carry/no-carry decision and final Excess-3 correction separate.
09 · GRAY CODE

Only one bit changes between consecutive code words.

Gray code is a non-weighted unit-distance code. Consecutive values differ in only one bit position. It is also commonly called reflected binary code. The one-bit-change property is useful in systems such as position encoders because a transition is less likely to be misread when several physical bits cannot change at exactly the same instant.

10 · BINARY ↔ GRAY CONVERSION

The conversion becomes simple when you remember XOR.

Binary → Gray

Copy the binary MSB directly. Each following Gray bit is the XOR of the current binary bit and the binary bit immediately before it.

Binary 1011 → Gray 1110

Gray → Binary

Copy the Gray MSB. Each next binary bit is obtained by XORing the previous binary result with the current Gray bit.

Gray 1110 → Binary 1011

XOR: equal bits give 0; different bits give 1. Thus 0⊕0=0, 1⊕1=0, 0⊕1=1 and 1⊕0=1.
11 · ALPHANUMERIC CODES

Binary patterns can represent characters, not only numbers.

ASCII stands for American Standard Code for Information Interchange. Standard ASCII uses 7 bits, giving 2⁷ = 128 possible code values. The higher and lower bits together identify entries in the predefined ASCII character table. ASCII became fundamental in computers and digital communication; later character encodings such as Unicode support vastly larger sets of writing systems and symbols.

A–Z

ASCII decimal 65–90. Example: A = 65 = 1000001.

a–z

ASCII decimal 97–122.

0–9

ASCII decimal 48–57. Notice: character '5' is not stored as numeric value 5.

Other alphanumeric codes include EBCDIC and Hollerith. EBCDIC is an 8-bit character encoding associated with IBM systems; 8 bits provide 256 possible bit patterns.

12 · ERROR DETECTION: PARITY

Add one extra bit so some transmission errors become visible.

A parity bit is appended so the total number of 1s is even (even parity) or odd (odd parity). A parity generator creates the bit at the transmitter and a parity checker verifies it at the receiver.

Even-parity example

Data 1011001 contains four 1s, already even, so the even-parity bit is 0. If a single transmitted bit flips, the receiver's parity check fails.

Limitation: one parity bit detects any odd number of bit errors, including every single-bit error, but it cannot identify which bit is wrong and cannot detect every even-number-of-bit-errors pattern.
13 · HAMMING CODE

Multiple parity checks can locate a single-bit error.

Hamming code places parity bits at positions that are powers of two: 1, 2, 4, 8, …. Each parity bit checks a particular group of positions. At the receiver, the combined parity-check results form a syndrome; for a single-bit error, that syndrome identifies the erroneous position so the bit can be corrected.

Important distinction: standard Hamming code has minimum distance 3 and is normally described as single-error correcting (SEC). Adding one extra overall parity bit gives extended Hamming / SECDED: Single Error Correction, Double Error Detection.
