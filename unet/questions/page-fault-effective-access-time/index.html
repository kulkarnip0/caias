Effective memory access time when a page fault occurs once in 100 instructions

Question

Given memory access time as p nanoseconds and additional q nanoseconds for handling the page fault. What is the effective memory access time if a page fault occurs once for every 100 instructions?

Options: A) p + q/100    B) (p + q)/100    C) p + q    D) p/100 + q

First understand the story — no formula yet

Imagine a child fetching a toy from a cupboard

Every time the child needs a toy, the child first looks in the nearby cupboard. If the toy is there, the job is easy. Suppose that normal trip takes p seconds.

Sometimes the toy is not in the cupboard. Then the child has to go to a far-away store room, bring the toy back, put it in the cupboard, and continue. Suppose that extra trouble takes q seconds.

So the picture is: 99 × p and 1 × (p+q).

The whole trick: p happens on all 100 accesses. q happens only once. So when we average, the 100 copies of p become just p, while the single q gets spread over 100 accesses and becomes q/100.

Now reveal the reasoning one small step at a time

1. What does memory access mean?

The CPU often needs something from memory: an instruction, a number, a variable, or some data. Asking RAM for that item is a memory access.

CPU asks for data→RAM gives data

The question tells us one normal memory access takes:

p nanoseconds
So every normal access pays p.

2. What is a page, and what is a page fault?

Programs are divided into chunks called pages. The CPU wants the needed page to be in fast main memory (RAM).

Program page

A chunk of the program/data.

RAM

Fast place where active pages should be.

Page fault

The needed page is not currently in RAM.

Kid picture: the toy exists, but it is not in the nearby cupboard. You must fetch it from somewhere farther away.

3. What exactly does p mean?

normal memory access time = p ns

If there is no page fault, the computer simply spends p nanoseconds.

Important: p is not a rare cost. p is the normal cost that happens every time.

4. What exactly does “additional q” mean?

This one word — additional — is very important.

If a page fault occurs, the computer does not magically skip the normal memory work. The fault creates extra work.

normal part = p extra page-fault handling = q faulting access = p + q
Kid picture: you still went to the cupboard first. Only after discovering the toy was missing did you make the extra store-room trip.
Common mistake: saying the faulting access costs only q. That would ignore the word “additional.”

5. What does “once for every 100 instructions” mean?

Take a group of 100 instructions. In the simplified model intended by the question:

99

do not suffer a page fault

time = p each
1

suffers a page fault

time = p + q

The page-fault rate is therefore:

1 / 100 = 0.01 = 1%
If you draw 100 boxes, only one box gets the extra +q.

6. Count the p's before doing any algebra

This is the easiest way to avoid confusion.

Instruction 1 → p Instruction 2 → p Instruction 3 → p ... Instruction 99 → p Instruction 100 → p + q

How many copies of p are there?

99 copies of p + 1 more copy of p = 100 copies of p
The page fault adds q. It does not remove the p from that instruction.

7. Total time for the 99 normal instructions

Each normal instruction costs p, and there are 99 of them:

99 × p = 99p

8. Time for the one faulting instruction

The one unlucky instruction pays the normal cost plus the extra fault cost:

p + q

9. Add all 100 instructions

Now combine the 99 normal instructions and the one faulting instruction:

total time = 99p + (p + q) = 99p + p + q = 100p + q
Pause here: this is the total for all 100 instructions, not yet the average for one instruction.

10. Why do we divide by 100?

The question asks for the effective or average access time. We just found the total time of a batch containing 100 accesses.

If 100 children together use 1,100 seconds, and you want the average time per child, you divide the total by 100.

average = total time / number of accesses EAT = (100p + q) / 100

11. Simplify very slowly

EAT = (100p + q) / 100

Split the numerator into two pieces:

EAT = 100p/100 + q/100

Now simplify the first part:

100p/100 = p

So:

EAT = p + q/100
Correct answer: A) p + q/100

12. Why does p remain p, but q becomes q/100?

This is the most important idea in the whole question.

p

p happens on all 100 accesses.

100p / 100 = p

So averaging does not shrink the normal cost away.

q

q happens on only 1 of the 100 accesses.

q / 100

So the rare extra cost is spread across all 100 accesses.

normal cost every time = p+rare extra cost = q/100

13. Same answer using probability

Once the 100-access picture is clear, the probability formula becomes easy.

CaseProbabilityTime
No page fault99/100p
Page fault1/100p + q
EAT = (99/100)p + (1/100)(p + q) = 99p/100 + p/100 + q/100 = 100p/100 + q/100 = p + q/100
This is exactly the same reasoning as the 100-box method, just written using probabilities.

14. Tiny numerical example

Use easy numbers so you can feel what the formula is doing.

p = 10 ns q = 100 ns

For 99 normal accesses:

99 × 10 = 990 ns

For the one faulting access:

10 + 100 = 110 ns

Total for 100 accesses:

990 + 110 = 1100 ns

Average per access:

1100 / 100 = 11 ns

Now check the formula:

p + q/100 = 10 + 100/100 = 10 + 1 = 11 ns
The extra 100 ns fault penalty happens only once in 100 accesses, so it adds only 1 ns to the average.

15. Why are the other options wrong?

OptionWhy
A) p + q/100Correct: p happens every time; q happens once in 100.
B) (p + q)/100Wrong because it divides the normal p by 100, even though p happens on every access.
C) p + qWrong because it acts as though a page fault happens on every access.
D) p/100 + qWrong for both reasons: it makes p rare and q happen every time, exactly opposite to the question.

16. One picture to remember for the exam

100 accesses: 99 normal: 99p 1 page fault: p + q ----- total: 100p + q average: (100p + q)/100 = p + q/100
Memory sentence: “Normal cost p every time, rare extra cost q only once in 100.”
Exam-model note: the question is using the simplified interpretation that the stated page-fault frequency applies to the accesses/instructions being averaged. Under that intended model, the answer is unambiguously A.
