Binary Codes: how information becomes 0s and 1s.

A computer does not directly understand the letter A, the number 7, a photograph, or an audio recording. Information must be represented as patterns of 0s and 1s so that it can be stored, processed and transmitted.

01 · WHY DO WE STUDY BINARY CODES?

Because every kind of information needs a binary representation.

Binary coding is the process of representing information using sequences of 0s and 1s. The information may be a character, number, image, sound or some other data. To store it in a computer, it is first encoded into a binary pattern. To understand or display it again, the pattern is decoded.

Simple idea: a binary code is like an agreement between humans and the computer. We decide which bit pattern represents which symbol or value. Without that agreement, a sequence such as 1000001 is only a pattern of bits.

⌨️ Typing

When you press a key such as A, the computer stores a predefined binary code for that character.

📡 Communication

Digital systems need standard codes so that one device can send data and another device can interpret it correctly.

🔢 Digital arithmetic

Different numeric codes are useful for representing decimal digits and for simplifying particular digital operations.

03 · ALPHANUMERIC CODES

Codes for letters, digits and symbols.

Alphanumeric codes represent character sets: alphabets, numbers, punctuation and control characters. Two basic examples discussed in the reference are ASCII and EBCDIC.

ASCII

ASCII stands for American Standard Code for Information Interchange. It uses 7 bits.

1000001

2⁷ = 128 possible patterns

Three higher-order bits can identify one of 8 columns, while four lower-order bits can identify one of 16 rows in an ASCII chart.

EBCDIC

EBCDIC stands for Extended Binary Coded Decimal Interchange Code. It uses 8 bits.

01100001

2⁸ = 256 possible patterns

The additional bit doubles the number of possible bit patterns compared with a 7-bit code.

Why bit count matters: with n bits, the number of different patterns is 2ⁿ. Therefore 7 bits can form 128 patterns, while 8 bits can form 256 patterns.
04 · ASCII EXAMPLE: WHY DOES A = 65?

Read the bits using their positional values.

The reference uses uppercase A as a simple ASCII example. Its 7-bit binary form is 1000001. The leftmost 1 contributes 2⁶ = 64 and the rightmost 1 contributes 2⁰ = 1.

2⁶ = 641
2⁵ = 320
2⁴ = 160
2³ = 80
2² = 40
2¹ = 20
2⁰ = 11

64 + 1 = 65 → uppercase A

Student check: if you see 1000010, the two 1s represent 64 and 2, giving 66. This shows how a bit pattern can be connected to a predefined character code.
05 · NUMERIC CODES

Numeric codes can be weighted or non-weighted.

A numeric code represents decimal digits using binary patterns. In a weighted code, each bit position has an assigned weight. The value of the digit is obtained by adding the weights corresponding to the bit positions that contain 1.

Weighted example: 8-4-2-1

The four positions have weights 8, 4, 2 and 1.

06 · SELF-COMPLEMENTARY IDEA

Toggle the bits—and the represented digit can become its 9's complement.

The transcript illustrates this using the weighted code 8-4-(-2)-(-1). Pattern 0111 represents 1. If every bit is toggled, we obtain 1000, which represents 8.

0111

4 - 2 - 1 = 1

One's complement

Toggle every bit: 0↔1

1000

8 = 8

The digits 1 and 8 are 9's complements because 9 - 1 = 8. In a self-complementary code, the code of a digit and the code of its 9's complement are one's complements of each other.
07 · NON-WEIGHTED NUMERIC CODES

No fixed positional weights are used.

Gray Code

Gray code is also called a Unit Distance Code. The reference highlights it as an important non-weighted numeric code with many applications.

Excess-3

Excess-3 is another non-weighted numeric code. The reference notes that it is sequential and self-complementary.

Key difference

Unlike 8-4-2-1 or 2-4-2-1, these codes are not interpreted by simply multiplying each bit by a fixed positional weight.
