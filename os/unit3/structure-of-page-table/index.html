Structure of the Page Table

How does a computer find the correct place in RAM when a program uses a virtual address? Begin with the simplest idea of memory and learn step by step how hierarchical, hashed and inverted page tables work.

01 · STRUCTURE OF PAGE TABLE

What is memory?

What does it mean?

A running program needs somewhere to keep its instructions and data. Main memory, also called RAM, holds information that the CPU can access quickly. A program normally works with virtual addresses; the memory-management hardware and operating system translate them into locations in physical RAM.

Simple example

Imagine a building with numbered apartments. A person may know a friend's apartment number, but a building directory is needed to find the correct physical location. Address translation plays a similar role.

02 · STRUCTURE OF PAGE TABLE

What are pages and frames?

What does it mean?

Paging divides a process's virtual address space into fixed-size blocks called pages. Physical RAM is divided into equally sized blocks called frames. A virtual page can be placed into an available physical frame. Pages and frames have the same size, so a page fits exactly inside a frame.

Simple example

If the page size is 4 KB, then each page holds 4096 bytes. A program's page 0 might be in RAM frame 7 while its page 1 might be in frame 2. The frames need not be next to one another.

03 · STRUCTURE OF PAGE TABLE

What is a page table?

What does it mean?

A page table is a mapping structure that helps translate a virtual page number into a physical frame number. A typical page-table entry also carries information such as whether the mapping is present and what accesses are permitted. Different systems store and organize these entries in different ways.

Simple example

Think of a page table as a directory: page 0 → frame 7; page 1 → frame 2; page 2 → frame 9. The CPU uses the directory rather than guessing where each page was placed.

04 · STRUCTURE OF PAGE TABLE

Page number and offset

What does it mean?

A virtual address has two useful parts: the virtual page number and the offset. The page number identifies which page contains the desired byte. The offset identifies the position of that byte inside the page. Translation changes the page number into a frame number, but the offset stays the same.

Simple example

With 4 KB pages, offset 100 means the 101st byte within a page if counting from zero. If page 3 maps to frame 8, the physical address is 8 × 4096 + 100 = 32868.

05 · STRUCTURE OF PAGE TABLE

Why do page-table structures matter?

What does it mean?

A simple page table may need an entry for every virtual page. With a very large virtual address space, a flat table can become enormous, even if a program uses only a small part of that space. The reference introduces three ways of organizing translation information: hierarchical paging, hashed page tables and inverted page tables.

Simple example

The problem is like keeping a separate directory page for every possible apartment number in a gigantic city, even when most buildings do not exist. A better directory can avoid storing many unnecessary entries.

06 · STRUCTURE OF PAGE TABLE

Hierarchical paging: a directory of directories

What does it mean?

In hierarchical paging, the page table is divided into smaller page tables. An outer table tells us where to find an inner table, and the inner table tells us the physical frame. This is often called two-level paging. Additional levels can be used for larger address spaces.

Simple example

Imagine a library: first choose the correct bookshelf (outer table), then the correct book on that shelf (inner table), then the exact line inside the book (offset).

07 · STRUCTURE OF PAGE TABLE

Worked example: 32-bit virtual address

What does it mean?

The reference uses a 32-bit logical address with a 12-bit page offset. Because 2¹² = 4096, the page size is 4 KB. The remaining 20 bits identify the virtual page. In a two-level scheme, those 20 bits are split into 10 bits for the outer-table index and 10 bits for the inner-table index.

Simple example

Address layout: p₁ (10 bits) | p₂ (10 bits) | d (12 bits). The outer index selects an inner page table. The inner index selects an entry containing a frame number. The offset d locates the byte within that frame.

08 · STRUCTURE OF PAGE TABLE

Hierarchical paging: benefits and limitations

What does it mean?

Hierarchical paging can avoid allocating inner page tables for unused regions of a sparse virtual address space. The design is therefore especially useful when the address space is much larger than the memory actually used. It can also require more than one table lookup on a translation that misses in the translation lookaside buffer (TLB).

Simple example

An important detail: a page-table level is a lookup step, not a new copy of the program's data. The actual data still resides in physical frames or may be absent from RAM.

09 · STRUCTURE OF PAGE TABLE

Hashed page tables: find a mapping using a hash

What does it mean?

A hashed page table applies a hash function to a virtual page number to choose a bucket. A bucket can hold a chain of entries because different virtual page numbers may hash to the same location. Each entry in the reference contains a virtual page number, a mapped frame and a pointer to the next entry.

Simple example

Think of sorting names into boxes by their first letter. Several names may end up in the same box, so you check the names inside until you find the correct one.

10 · STRUCTURE OF PAGE TABLE

Hashed page table: lookup step by step

What does it mean?

First, take the virtual page number from the virtual address. Second, compute its hash bucket. Third, compare the virtual page number with entries in that bucket. Fourth, if a matching mapping is found, obtain its frame number. Finally, combine the frame number with the original offset to form the physical address.

Simple example

Example: suppose hash(page) = page mod 4. Pages 5 and 9 both select bucket 1. If the bucket contains (5 → frame 3) and (9 → frame 6), looking for page 9 requires comparing entries until page 9 is found.

11 · STRUCTURE OF PAGE TABLE

What is a hash collision?

What does it mean?

A collision happens when different virtual page numbers produce the same hash bucket. A collision does not mean the two pages are identical or that one overwrites the other. The bucket must distinguish them, for example with a linked list. Long chains can slow down lookup.

Simple example

In the example above, 5 mod 4 = 1 and 9 mod 4 = 1. Both go to bucket 1, but their complete page numbers remain different.

12 · STRUCTURE OF PAGE TABLE

Inverted page tables: one entry per physical frame

What does it mean?

A conventional page table is commonly organized around a process's virtual pages. An inverted page table instead has an entry for each physical frame, recording which process and virtual page currently occupy that frame. Its size therefore depends primarily on the number of physical frames, not on the total number of possible virtual pages across processes.

Simple example

Think of a parking lot. Rather than keeping a huge list of every car that could ever arrive, keep one record for each actual parking space showing which car is parked there.

13 · STRUCTURE OF PAGE TABLE

Why does an inverted table need a process ID?

What does it mean?

Different processes may use the same virtual page number. For example, both process A and process B may refer to virtual page 4, but those pages can contain completely different data. The pair (process ID, virtual page number) identifies which mapping is requested.

Simple example

A virtual address can be viewed as (process ID, page number, offset) for this lookup. If the matching entry is at physical-frame index i, the resulting physical address is (i, offset).

14 · STRUCTURE OF PAGE TABLE

Inverted page tables: trade-offs

What does it mean?

An inverted table can save memory because it has roughly one entry per physical frame. However, finding a matching process/page pair is more involved than direct indexing into a conventional page table; implementations may use hashing or other supporting structures. Shared pages and aliases also require careful handling because one physical frame can correspond to multiple virtual addresses.

Simple example

There is no universal winner. The best design depends on address-space size, memory usage, processor architecture and translation hardware.

15 · STRUCTURE OF PAGE TABLE

How does the TLB help?

What does it mean?

A translation lookaside buffer, or TLB, is a small fast cache of recent virtual-to-physical address translations. When the requested translation is in the TLB, the processor can often avoid walking the page tables. When it is not there, a page-table lookup or walk is needed, depending on the architecture.

Simple example

The TLB is like keeping the most recently used addresses on a small sticky note, so you do not need to search the full directory every time.

16 · STRUCTURE OF PAGE TABLE

Page-table miss versus page fault

What does it mean?

Not finding a translation in the TLB is called a TLB miss; it does not necessarily mean the page is absent from RAM. A page fault is an exception raised when a memory reference cannot be completed with the current mapping—for example, when a valid page needs to be brought into RAM or an access violates permissions. The operating system handles the fault according to its cause.

Simple example

A missing shortcut in your notebook is not the same as a missing book in the library. The first may require looking up the directory; the second may require fetching the book or denying the request.

17 · STRUCTURE OF PAGE TABLE

Comparison: three structures

What does it mean?

Hierarchical paging uses several levels of tables and is useful for sparse address spaces. Hashed paging uses a hash of the virtual page number and handles collisions within buckets. Inverted paging records the virtual-page owner of each physical frame and can reduce the total table size. All three help with virtual-to-physical address translation.

Simple example

Remember the key images: hierarchical = folders inside folders; hashed = labelled buckets; inverted = one record per parking space.

Check the concepts

What is the difference between a page and a frame?

A page is a fixed-size block in virtual memory; a frame is an equally sized block in physical RAM.

What happens to the offset during translation?

The offset remains unchanged. The virtual page number is translated to a physical frame number.

For a 32-bit address and 12-bit offset, how many page-number bits remain?

20 bits, because 32 − 12 = 20.

What are p₁ and p₂ in two-level paging?

p₁ indexes the outer page table; p₂ indexes an entry in the selected inner page table.

Why do hashed page tables need collision handling?

Different virtual page numbers can hash to the same bucket.

Why is a process ID used with an inverted page table?

Different processes can use the same virtual page number, so the process ID distinguishes their mappings.

Is a TLB miss automatically a page fault?

No. The translation may still be present in the page tables and the page may already be in RAM.
