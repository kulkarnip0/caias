02 · WHY MULTITHREADING?

Four benefits

Responsiveness

One thread may wait for I/O while another continues handling the user interface or other work.

Resource sharing

Threads communicate cheaply because they share the same process memory and files.

Economy

Creating and switching threads usually requires less work than creating and switching full processes.

Scalability

Multiple runnable kernel-schedulable threads can execute on multiple CPU cores at the same time.

03 · USER THREADS VS KERNEL THREADS

Two layers of threading

User-level thread

Managed in user space by a runtime or thread library. User-thread operations may be fast because not every action needs a kernel transition.

Kernel-level thread

Known to the operating-system kernel. Kernel threads are the entities the OS can schedule onto CPU cores.

The central question of the models: how many user threads are mapped to how many kernel threads?

06 · MODEL COMPARISON

What changes from one model to another?

ModelMappingBlocking effectParallelism on multicoreMain trade-off
Many-to-OneMany user → one kernelA blocking kernel call can block all user threads using that kernel threadNo true parallelism for these user threadsLow overhead, poor concurrency
One-to-OneEach user → one kernelOther threads can continueYesGood concurrency, more kernel-thread overhead
Many-to-ManyMany user → many kernelBlocking one kernel thread need not stop all user threadsYes, limited by kernel threads and coresFlexible but more complex
Two-LevelMany-to-many plus optional bindingSimilar to many-to-manyYesExtra control through binding
Memory aid: Many-to-One is restrictive, One-to-One is direct, Many-to-Many is flexible, and Two-Level is Many-to-Many plus optional binding.
