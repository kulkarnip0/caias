How many virtual pages? How large is the page table?

The question

Given a 4 GB virtual address space, a typical page size of 4 KB, and a page table entry size of 5 bytes:

  1. How many virtual pages does this imply?
  2. What is the size of the whole page table?

We assume binary memory units: 1 KB = 1024 bytes and 1 GB = 1024³ bytes. We also assume a single-level page table with one entry per virtual page.

1 · First, what is memory?

Imagine a huge cupboard. The cupboard has many tiny storage positions. A computer's memory stores information in bytes, and each byte can be identified by an address. An address is simply a number telling the computer where to look.

A virtual address space is the range of addresses that a program can use. Think of it as a numbered map given to the program. Those addresses do not necessarily correspond directly to the same positions in physical RAM.

Here, the virtual address space is 4 GB. That tells us how much virtual address space exists, not how much physical RAM must actually be installed or used.

2 · What is a page?

Instead of managing every byte individually, the operating system divides the virtual address space into equally sized blocks called pages. In this question, each page holds 4 KB = 4096 bytes.

Imagine cutting a long strip of paper into equal pieces. The whole strip represents the virtual address space, and each piece represents a page. Every piece has the same size, except in other settings where special page sizes may be supported.

3 · What is physical memory, and what is a frame?

Physical memory means actual RAM. RAM is also divided into fixed-sized blocks called frames. A virtual page can be placed into a physical frame of the same size. The page number identifies a virtual block; the frame number identifies a block in RAM.

A page might not currently be in RAM. The operating system can arrange to load it when needed. That is one reason virtual memory is useful: programs can work with a virtual address space without requiring every page to occupy RAM at the same time.

4 · What is a page table?

A page table is a mapping structure used by the operating system and memory-management hardware. It helps translate a virtual page number into a physical frame number when the page is present. Entries also commonly contain status or protection information.

5 · What is a page table entry (PTE)?

A page table entry is one record inside the page table. Think of a page table as a list and each PTE as one row. The row may hold a physical frame number and flags such as present/valid, permissions or other control bits.

The question tells us that each entry occupies 5 bytes. That is a given value for this numerical problem, not a universal page-table entry size for every computer.

Key difference: Page size = how much virtual data fits in one page. PTE size = how much storage is used for one page's mapping record. Here they are 4096 bytes and 5 bytes respectively.

6 · Convert the units carefully

Memory questions commonly use powers of two. We write out the conversions so no step is hidden.

1 KB = 2¹⁰ bytes = 1024 bytes
1 GB = 2³⁰ bytes = 1,073,741,824 bytes

Therefore:

4 GB = 4 × 2³⁰ = 2³² bytes
4 KB = 4 × 2¹⁰ = 2¹² bytes

Notice that 4 is itself 2². That is why 4 × 2³⁰ becomes 2³², and 4 × 2¹⁰ becomes 2¹².

7 · Calculate the number of virtual pages

Think about a box holding 20 chocolates. If each packet contains 5 chocolates, the number of packets is 20 ÷ 5 = 4. We use exactly the same logic for pages:

Number of pages = Total virtual space ÷ Size of one page
= 2³² ÷ 2¹² = 2²⁰
= 1,048,576 virtual pages

When dividing powers of two with the same base, subtract the exponents: 32 − 12 = 20.

Virtual pages can be numbered from 0 to 1,048,575. The numbering begins at zero, so the highest page number is one less than the total count.

8 · Calculate the complete page-table size

Under the single-level assumption, every virtual page has one page-table entry. So if there are 1,048,576 virtual pages, there are also 1,048,576 entries.

Page-table size = Number of entries × Size of each entry
= 1,048,576 × 5 bytes
= 5,242,880 bytes

To convert bytes into MiB, divide by 1024 twice. One mebibyte (MiB) contains 2²⁰ bytes:

5,242,880 ÷ 1,048,576 = 5 MiB

Many examination questions informally write this as 5 MB, using binary conventions. More precisely, it is 5 MiB, approximately 5.24 decimal MB.

Final answer

Number of virtual pages = 1,048,576 = 2²⁰ pages.

Whole page table size = 5,242,880 bytes = 5 MiB.

9 · See how a virtual address is divided

A 4 GB byte-addressable virtual space contains 2³² addresses, so a virtual address can be represented using 32 bits. A 4 KB page holds 2¹² bytes, so the position within a page (called the offset) needs 12 bits. The remaining 20 bits identify the virtual page.

Virtual page number20 bits
Offset within page12 bits

For example, virtual address 4097 is one byte after the start of virtual page 1. Since page 0 covers addresses 0–4095, page 1 starts at address 4096. So the virtual page number is 1 and the offset is 1.

The page table maps page 1 to a physical frame. The offset remains 1 inside that physical frame. This is how a virtual address can be translated into a physical address.

10 · Why can the page table be so large?

A single-level page table reserves one entry for each possible virtual page in this simplified model. Even if a program is actively using only a small fraction of its virtual address space, the complete flat table calculated here would occupy 5 MiB.

Real operating systems may use multilevel page tables, demand allocation and other techniques to avoid storing every possible mapping entry in one flat table. Therefore 5 MiB is the answer for the specified whole, single-level page table; it is not a claim that every real process always consumes exactly 5 MiB of page-table RAM.

11 · Common mistakes

Mistake 1: Multiplying 4 GB by 4 KB. To count blocks, we must divide total size by block size.

Mistake 2: Confusing 5 bytes per entry with 5 bytes per page. One page contains 4096 bytes of virtual data; its mapping record occupies 5 bytes in this question.

Mistake 3: Writing 2³² pages. 2³² counts byte addresses, not pages. Divide by 2¹² bytes per page to obtain 2²⁰ pages.

Mistake 4: Assuming page-table size equals physical RAM size. The page table stores mappings, not all the actual contents of the pages.

12 · Check your understanding

If a page size increases while virtual space stays the same, what happens to the number of pages?

The number decreases, because larger pages mean fewer blocks are needed to cover the same total space.

If the number of pages stays the same but each PTE doubles in size, what happens to page-table size?

It doubles, because total size = number of entries × bytes per entry.

What is the difference between a page and a frame?

A page is a block of virtual address space. A frame is a corresponding-sized block of physical RAM.

How many bits are used for page number and offset in this problem?

20 bits for virtual page number and 12 bits for the offset, totalling 32 bits.
